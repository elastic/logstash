# Logstash smart exhaustive tests pipeline

Selectively triggers the exhaustive Logstash test suite for pull requests that touch acceptance-test code or request it by comment.

## At a glance

| | |
| --- | --- |
| Platform | Buildkite |
| Pipeline | [`logstash-smart-exhaustive-tests-pipeline`](https://buildkite.com/elastic/logstash-smart-exhaustive-tests-pipeline) |
| Source | [`smart_exhaustive_tests_pipeline.yml`](../smart_exhaustive_tests_pipeline.yml) and [`pull-requests.json`](../pull-requests.json) |
| Trigger | Pull requests and comments enabled through the repository's Buildkite pull-request integration. |

## Purpose

The pipeline avoids running the exhaustive acceptance suite for every change. It triggers the separate exhaustive pipeline when watched acceptance-test paths change or when a matching pull-request comment requests it.

## When it runs

Live Buildkite settings enable pull-request builds, disable fork builds, and filter to builds created by `elasticmachine` with a pull-request ID. `.buildkite/pull-requests.json` enables commit and comment triggers and commit-status publication. The configured command expression is case-sensitive and end-anchored: `^run\s+exhaustive\s+tests$` (one or more whitespace characters between words, no extra prefix or suffix). Its `always_trigger_comment_regex` is the same.

The file-change trigger watches `^qa/acceptance/`, `^ci/acceptance_tests.sh`, `^ci/docker_acceptance_tests.sh`, `^qa/docker/`, and `.buildkite/smart_exhaustive_tests_pipeline.yml`. The file-change step is suppressed when `GITHUB_PR_TRIGGER_COMMENT` begins with `run exhaustive tests` case-insensitively; the separate comment step uses a case-insensitive prefix condition. The integration's skip-only-changed patterns match the main pull-request pipeline; `^qa/acceptance/` and `^ci/acceptance_tests.sh` are configured as always-require paths. No skip labels or target branches are configured. Organization users are allowed; `admin`/`write` repository permissions qualify, with `dependabot[bot]`, `mergify[bot]`, and `github-actions[bot]` allowlisted.

## Execution flow

| Job or step | Runs when | Depends on | What it does |
| --- | --- | --- | --- |
| Trigger for watched changes | Pull request with at least one watched changed path and no comment prefix matched by the step condition | None declared | Triggers `logstash-exhaustive-tests-pipeline` at the current commit and branch, forwarding pull-request metadata and disabling Slack notifications. |
| Trigger for comment | `GITHUB_PR_TRIGGER_COMMENT` matches the case-insensitive `^run\s+exhaustive\s+tests` prefix condition in the YAML | None declared | Triggers the exhaustive pipeline at `HEAD` on `pull/<number>/merge`, forwarding pull-request metadata and disabling Slack notifications. |

## Inputs, outputs, and access

| Item | Details |
| --- | --- |
| Inputs | Pull-request changed-file list, `GITHUB_PR_TRIGGER_COMMENT`, and Buildkite commit/branch/PR variables. |
| Outputs | A downstream Buildkite build of `logstash-exhaustive-tests-pipeline`; no local artifacts are declared. |
| Permissions | Buildkite pull-request integration publishes commit status. |
| Trigger access | Organization users, `admin`/`write` repository permissions, and the explicit bot allowlist described above. |

## Operational notes

This YAML only selects and triggers the exhaustive pipeline; it does not contain the exhaustive tests themselves. The runtime test matrix is generated by the destination pipeline.
